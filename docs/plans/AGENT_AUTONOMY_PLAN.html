1. המצב הקיים — מה שבור

🔴 הבעיה המרכזית: "הרץ סוכנים" לא באמת מריץ

כפתור "הרץ סוכנים" באדמין קורא ל-route ?type=run שרץ רק על משימות עם status=approved. זה אומר:

  • כל משימה חדשה נוצרת בסטטוס pending_approval ← מחכה לאישור ידני שלך
  • אתה לוחץ "אשר לביצוע" ← הסטטוס הופך ל-approved
  • אתה לוחץ "הרץ סוכנים" ← ה-run route שולף את ה-approved ומעבד
  • אבל: הסוכן marketing מחזיר את המשימה ל-pending_approval אחרי עיבוד (כי הוא מייצר תוצאה שדורשת "אישור שלך")

התוצאה: לולאה אינסופית — אשר → הרץ → חוזר לאישור → אשר שוב → ...

📊 מפת סטטוסים לכל סוכן — מה באמת קורה

סוכן מה הוא עושה ב-run סטטוס אחרי run בעיה
content מייצר קופי + תמונה via Gemini pending_approval עובד — אבל דורש אישור לפרסום
marketing מייצר ניתוח SEO/שיווק via Gemini pending_approval לולאה — מחזיר לאישור אחרי כל run
cto מייצר תוכנית טכנית via Gemini in_progress תקוע — נשאר in_progress לנצח
supply מעביר ל-in_progress (סנכרון Gelato נפרד) in_progress תקוע — אף פעם לא מגיע ל-done
כל השאר מעביר ל-in_progress בלי פעולה אמיתית in_progress ריק — לא עושה כלום מעבר לשנות סטטוס

2. המצב הרצוי — מה אתה רוצה

✅ העקרונות

  • אוטונומיה מלאה: כל המשימות רצות בלי אישור ידני שלך
  • חריג יחיד: משימות שדורשות הוצאת כסף (קמפיינים, רכישות) — דורשות אישור
  • דוח יומי מפורט: מה רץ, מה נעשה, מה הצליח, מה נכשל — במייל הבוקר
  • לוג פעולות: כל סוכן מתעד מה עשה ב-notes של המשימה

📋 הפלו החדש

Task created → AUTO-EXECUTE (no approval needed)
├── content agent → generate caption + image → QA → auto-publish → done
├── marketing agent → generate analysis → save to notes → done
├── cto agent → generate tech plan → save to notes → done
├── supply agent → sync Gelato → save results → done
└── any agent → run Gemini analysis → save → done

EXCEPTION: category === 'campaign' || has_budget === true
└── stays in pending_approval → requires oren's OK

3. השינויים הנדרשים

שינוי 1: Edge Function — ?type=run route

מה: שינוי ה-run route כך שירוץ על משימות pending_approval ישירות (לא רק approved)

חריג: משימות עם category='campaign' או requires_budget=true — נשארות ב-pending_approval

סטטוסים חדשים:

  • marketing agent → אחרי ניתוח → status=done (לא pending_approval)
  • cto agent → אחרי תוכנית טכנית → status=done
  • supply agent → אחרי סנכרון → status=done
  • Default agents → לא רק שינוי סטטוס, אלא ניתוח Gemini + done

⏱ מאמץ: בינוני | השפעה: גבוהה

שינוי 2: Cron חדש — הרצת משימות אוטומטית

מה: הוספת route חדש ל-morning-report.js: ?type=auto-run

ירוץ פעמיים ביום (08:00 + 14:00 ישראל) ויקרא ל-?type=run אוטומטית — בלי שתלחץ כפתור

הפלו:

cron 06:00 UTC → morning-report?type=auto-run
→ fetch Edge Function ?type=run (with CRON_SECRET)
→ processes all non-budget tasks automatically
→ logs results to agent_runs table

cron 12:00 UTC → same (catches afternoon tasks)

⏱ מאמץ: נמוך (route חדש בקובץ קיים) | השפעה: גבוהה

שינוי 3: דוח בוקר מורחב — פירוט פעולות סוכנים

מה: הרחבת ה-Morning Report Email עם סקשן חדש: "🤖 פעולות סוכנים ב-24 שעות האחרונות"

יישלף מטבלת agent_runs ויציג:

  • שם הסוכן + כמות משימות שטיפל
  • סטטוס (הצלחה / שגיאה)
  • סיכום מה נעשה (מ-summary)
  • משימות שנכשלו + סיבה

⏱ מאמץ: בינוני | השפעה: בינונית

שינוי 4: Admin UI — עדכון מסך משימות

מה:

  • הסרת כפתור "אשר לביצוע" ממשימות שלא דורשות תקציב
  • הוספת תגית אוטומטי למשימות שירוצו אוטומטית
  • השארת "אשר לביצוע" רק למשימות עם requires_budget=true
  • כפתור "הרץ סוכנים" נשאר — כאפשרות ידנית מהירה

⏱ מאמץ: בינוני | השפעה: בינונית

שינוי 5: CLAUDE.md — הסרת מגבלת "Nothing publishes without oren's approval"

מה: עדכון ה-CLAUDE.md וה-agents-system.md כך ש:

  • Phase 1 autonomy → Phase 2 autonomy (full auto, budget exceptions only)
  • הסרת "Nothing publishes without oren's approval"
  • הוספת "Budget-related tasks require oren's approval"

⏱ מאמץ: נמוך | השפעה: גבוהה

4. DB Schema — שינוי קטן

הוספת עמודה requires_budget BOOLEAN DEFAULT false לטבלת agent_tasks

משימות שדורשות כסף (קמפיינים ממומנים, רכישות) יסומנו requires_budget=true ← רק אלה יצטרכו אישור.

כל משימה שנוצרת אוטומטית ← requires_budget=false ← רצה ישר.

8. הדעה המקצועית שלי

אתה צודק ב-100%. המצב הנוכחי של מסך המשימות הוא תיאטרון אוטומציה — נראה כאילו יש סוכנים, אבל בפועל רוב הזמן אתה מאשר ידנית משימות שחוזרות לאותו מקום.

הפתרון פשוט יחסית: לתת לסוכנים לעבוד ולדווח אחורה, במקום לבקש רשות קדימה. ה-Content pipeline כבר עובד ככה (auto-content → generate → QA → publish). רק צריך להחיל את אותו עיקרון על כל שאר הסוכנים.
